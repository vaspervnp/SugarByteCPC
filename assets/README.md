# assets — ΠΑΡΑΓΟΜΕΝΑ

**Μην επεξεργάζεσαι τίποτα εδώ.** Όλα παράγονται από τη γεννήτρια στο
[`CPCArt/sugarbyte`](https://github.com/vaspervnp/CPCArt) και το επόμενο
`./sync-assets.sh` τα ξαναγράφει. Θέλεις άλλο candy; Άλλαξε τη γεννήτρια.

Αναλυτικά τι είναι το καθένα: **[`../plan.md` §3](../plan.md)**.

| | |
|---|---|
| `sprites.bin` | 13.696 bytes Mode 0 — **αυτό φορτώνει το παιχνίδι** (`incbin` στο `#4000`) |
| `menu.bin` | 5.808 bytes — τίτλος, μπορντούρα, μενού, κεφαλαία, εικονίδια. Φορτώνεται χωριστά· δες [`plan.md` §4.5](../plan.md) |
| `menu.asm` | οι σταθερές του δεύτερου blob |
| `sprites.asm` | οι σταθερές (`CANDY_SZ`, `CANDY_PLAIN`, …) και τα ίδια δεδομένα ως `db` |
| `sprites_map.txt` | πού κάθεται κάθε καρέ μέσα στο `sprites.bin` |
| `palette.gpl` | η παλέτα για GIMP/Aseprite, με τα firmware numbers |
| `manifest.json` | σύνοψη για εργαλεία: παλέτα, σετ, μεγέθη, διάταξη ταμπλό |
| `sheets/` | τα εννιά σετ ως PNG 16 χρωμάτων + πίνακας καρέ σε JSON |
| `aseprite/` | οι πηγές για πείραγμα με το χέρι (pixel ratio 2:1, tags) |
| `preview/` | κατάλογοι και οι δύο πλήρεις οθόνες, σε αναλογία 2:1 |

## Δύο πράγματα που θα σε φάνε

1. Οι σταθερές `_W` δίνουν bytes **ΔΕΔΟΜΕΝΩΝ** ανά γραμμή. Σε sprite με μάσκα
   η γραμμή πιάνει **2×** αυτό: `CANDY_W = 6` αλλά η γραμμή είναι 12 bytes και
   `CANDY_SZ = 288`.
2. Το **pen 0 είναι και το φόντο του ταμπλό και η μάσκα**. Γι' αυτό το
   περίγραμμα κάθε candy είναι η **σκιά του ίδιου του candy**, όχι μαύρο.
3. Στο Mode 0 το **bit 0 της πένας πάει στο πάνω bit του byte**, όχι το bit 3.
   Μη γράψεις αποκωδικοποιητή από μνήμη για να «επαληθεύσεις» το `sprites.bin`
   — θα τον γράψεις ανάποδα και θα βγάλει ψεύτικο συναγερμό.
